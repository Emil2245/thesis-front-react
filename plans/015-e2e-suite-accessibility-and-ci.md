## 1. Why this matters

Component tests prove screens behave; they do not prove the *flows* work. `08-codebase-design.md §9` assigns exactly six E2E cases to Playwright — deliberately few, because E2E is expensive and the api-level suite in the backend repo is authoritative for behaviour:

| Costura | Suite | Casos |
|---|---|---|
| Flujos completos | e2e (Playwright) | TC-P05-03 · TC-P06-04 · TC-P21-04 · TC-P35-01 · TC-P43-* |
| UI (hook/página) | Vitest + RTL + MSW | estados de S-xx; TC-P44-01 |

The CI gate matters for the thesis itself: `roadmap/01 §1` requires *"integración continua desde I-01 (GitHub Actions; una desviación GM ≠ 0.00 rompe el build)"*, and week 2's milestone is *"pipeline CI activo"*. The GM (golden master) suite lives in the backend repo; this plan builds the **frontend** pipeline and the gates that protect the frontend's own invariants.

## 3. How to run E2E without a backend

The Quarkus backend is a separate repository and may not be running. Two modes, both required:

- **Mode A (default, always green): MSW in the browser.** Playwright drives the real app with MSW's *browser* worker serving the same handlers the component tests use. This makes E2E deterministic and runnable in CI today.
- **Mode B (opt-in): against a live backend.** `E2E_BASE_URL` + a running API. Used before thesis milestones to prove the real integration.

Mode A is what CI runs. Note in your report that Mode A tests the frontend's flows, **not** the contract — the contract is tested by the backend's api suite plus `openapi-typescript` compile-time checking (plan 002).

## 5. Steps

### Step 1 — MSW browser worker

```bash
npx msw init public --save
```

Create `e2e/msw/browser.ts` starting the worker from the **same handler modules** the component tests use (`src/test/handlers.ts`), so there is one mock definition, not two. Start it in `src/main.tsx` behind a flag:

```ts
if (import.meta.env.VITE_MSW === "on") {
  const { worker } = await import("@/test/browser");
  await worker.start({ onUnhandledRequest: "warn" });
}
```

Add an npm script: `"dev:mock": "VITE_MSW=on vite"` and point `playwright.config.ts`'s `webServer.command` at it when `E2E_BASE_URL` is unset.

**Verify:** `npm run dev:mock` serves an app whose project list is populated from fixtures.

### Step 2 — Scenario fixtures

`e2e/fixtures/escenarios.ts` — named states the specs select via a header or query flag that MSW handlers read:

- `sin-proyectos` — for TC-P05-03
- `ci-no-configurado` — a project whose `alertas` contains `CI_NO_CONFIGURADO`, for TC-P06-04
- `apu-iess` — one real APU (reuse plan 009's fixture built from `../thesis-docs/plan/domain/_artifacts/`), for TC-P21-04
- `cronograma-poblado` — activities with active periods, for TC-P35-01
- `dos-versiones` — a project with two budget versions, one vigente, for TC-P43-02

`e2e/fixtures/sesion.ts` — a Playwright fixture that logs in (or seeds the session store) so specs do not each retype credentials.

### Step 3 — The specs

**`01-acceso.spec.ts` (TC-P43-01, TC-P43-02):**
- unauthenticated visit to `/proyectos/1/apus` → lands on `/login` with `?retorno=`; after logging in, lands back on the original URL;
- as `USUARIO`, the Admin section is absent from the sidebar and `/admin/usuarios` renders the 403 page;
- as `SUPER_ADMIN`, the Admin section is present;
- with `dos-versiones`: switching the version selector changes `?v=` in the URL, and navigating to `/presupuesto` and `/cronograma` keeps the chosen version.

**`02-proyectos.spec.ts` (TC-P05-03, TC-P06-04):**
- `sin-proyectos` → `/proyectos` shows the empty state with a "Crear proyecto" CTA;
- creating a project through the 3-step wizard lands on S-09;
- `ci-no-configurado` → S-09 shows the "%CI no configurado" alert and its link goes to `/parametros`.

**`03-apu.spec.ts` (TC-P21-04) — the most important spec in the file:**
- open S-22 with `apu-iess`;
- read the CT in the footer;
- edit a `cantidad` cell, press Enter;
- **assert the footer CT changes without any navigation or reload.** Capture `page.evaluate(() => performance.getEntriesByType("navigation").length)` before and after, or assert on a stable element identity, to prove no reload happened — the point of RNF-04 is precisely "sin recargar página";
- assert the HM row has no editable input;
- assert a row with an override shows the "manual" badge and the "restaurar herencia" action.

**`04-cronograma.spec.ts` (TC-P35-01):**
- open S-33 with `cronograma-poblado`;
- assert the Gantt renders one bar per activity, positioned over the active periods;
- assert both totals rows (por período, acumulado) are present with the fixture's values.

**`05-errores.spec.ts` (TC-P44-01):**
- force a 400 `validacion` on a form → the message appears **inline on the field**, in Spanish, and **no** toast fires;
- force a 409 → an explanatory dialog or alert appears;
- trigger a destructive action → a confirmation is required before the request goes out (assert the request count).

**`06-a11y.spec.ts`:**
Run `sinViolacionesA11y` (from plan 003's `e2e/axe.ts`) on the **N-priority screens**: S-01, S-07, S-09, S-12, S-14, S-20, **S-22**, S-27, S-33, S-35. `design/01 §8` requires keyboard-navigable grids and that colour is never the only signal; axe catches a useful subset.

Also add one explicit keyboard test on S-22 (not axe's job): tab into the grid, edit a cell, `Enter` moves down, `Escape` cancels.

### Step 4 — CI pipeline

`.github/workflows/ci.yml`:

```yaml
name: CI
on:
  push: { branches: [main] }
  pull_request:

jobs:
  verificar:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "22", cache: "npm" }
      - run: npm ci
      - run: npm run typecheck
      - run: npm run lint
      - run: npm run format:check
      - run: npm run test:coverage
      - run: npm run build
      - name: Sin aritmética de dinero en el cliente (ADR 9)
        run: |
          if grep -rnE "toFixed|parseFloat" src --include="*.ts" --include="*.tsx" \
             | grep -v "src/lib/decimal.ts"; then
            echo "::error::Se encontró formateo/aritmética numérica fuera de src/lib/decimal.ts (ADR 9, RNF-01)"
            exit 1
          fi
      - uses: actions/upload-artifact@v4
        if: always()
        with: { name: coverage, path: coverage/ }

  e2e:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "22", cache: "npm" }
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npm run e2e
      - uses: actions/upload-artifact@v4
        if: always()
        with: { name: playwright-report, path: playwright-report/ }
```

The `grep` gate is the mechanised version of the manual check every feature plan carried. It is the cheapest available protection for the thesis's `exactitud_calculo` variable — a client-side `toFixed` on a cost is exactly the kind of change that silently makes displayed numbers diverge from engine numbers.

Playwright's HTML report and traces are uploaded because `quality/01 §B4` calls them *"useful thesis evidence"*.

### Step 5 — Coverage reporting (report, don't gate)

`quality/01 §D.5` leaves enforced thresholds as an **open decision**. So: produce the report, upload it, and **do not fail the build on coverage**. Note the current numbers in your report so the humans can decide a threshold with data.

| Command | Expected |

| no route renders `Placeholder` anywhere | `grep -rn "Placeholder" src/routes` → no matches |

That last row is the completion check for the **whole plan set**: every screen S-01…S-44 has a real implementation.

## 7. Boundaries

- **Do not** write E2E for behaviour already covered at component level. Six flows plus a11y, not a mirror of the component suite. E2E is the most expensive and flakiest layer.
- **Do not** duplicate MSW handlers between `src/test/` and `e2e/msw/`. One source.
- **Do not** enforce a coverage threshold (open decision).
- **Do not** add Chromatic or paid visual testing. Playwright screenshots are the documented free option and `quality/01 §B7` defers them anyway.
- **Do not** add the backend's golden-master suite here. GM-01…GM-25 belong to the backend repo; the frontend's CI does not and cannot run them.

## 8. Escape hatches

- If MSW's browser worker cannot serve a flow (e.g. multipart CSV upload), skip that flow at E2E level, keep it at component level, and say so in your report — don't weaken the assertion to make it pass.
- If Kibo's Gantt DOM is untestable from Playwright, assert on the surrounding totals rows and the count of rendered bars, and report the limitation rather than deleting TC-P35-01.
- If a11y violations appear on shadcn-generated components, fix them in `src/components/ui/` (we own that code) — but if a fix would fight Radix's behaviour, report it instead of disabling the rule.
- If the CI grep gate produces false positives (a legitimate `parseFloat` in a non-money context), narrow it by path rather than deleting it.

## 9. Maintenance note

The grep gate and the six E2E specs are the two things most likely to be "temporarily" disabled under deadline pressure — which, per `roadmap/01 §6`, is exactly what the risk register anticipates: *"si la velocidad real es < 70 % de lo asumido, se recorta alcance por prioridad de pantallas — **nunca se recorta la suite GM ni el export**"*. The frontend equivalent of that rule: cut screens, never cut the ADR-9 gate.

When the backend becomes available, add a scheduled CI job running the E2E suite in Mode B against a deployed environment. That is the only way DTO drift between the two repos gets caught before a thesis milestone — until `openapi-typescript` generation replaces the hand-written contract (plan 002, `src/api/README.md`).
